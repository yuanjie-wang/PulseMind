## 一、识别与前置

### 1.1 这是什么文档

| 特征 | 值 |
|---|---|
| 分享页 URL | `doc.cmbchina.com/f/v?id=<docId>&mode=edit` |
| **内核形态** | ⭐ **主文档直接渲染，无 iframe**（`iframeCount: 0`）—— 四类中唯一 |
| **前置关卡** | ⚠️ **DLP 安全扫描**（主文件 §0.5）：页面显示 `DLP 安全扫描中...请耐心等待` 时**内容不加载**，需等扫描完成 |
| 编辑模式 | 按钮显示 `阅读` = 可编辑（主文件 §0.2 语义一致）|
| 正文形态 | **快照直读**：`generic` = 标题、**`paragraph` = 段落**、`N字` = 字数 |

**快速判定**：页面**无任何 iframe**（`iframeCount: 0`）+ 有 DLP 扫描提示 → **本文档**。

### 1.2 为什么它最好操作（四类中）

**不跨域** → 「点击难 / 定位器失效 / 坐标拿不到」**三个问题一个都不存在**：

| 能力 | 跨域的三类（Excel/多维/Word）| **智能文档** |
|---|---|---|
| Playwright 定位器 | ❌ 失效 | ✅ **可用** |
| `getBoundingClientRect` | ❌ null | ✅ 可用 |
| ref 前缀漂移 | ⚠️ 会变 | ✅ 稳定 |
| 精确点击 | ⚠️ 靠估 | ✅ **定位器点哪是哪** |

**★★ 别把跨域技巧带进来**：这里**不需要**名称框、不需要 ⌘C 取数、不需要前缀处理、不需要顶层直连（本身就是顶层）。

## 二、读

### 2.1 快照直读（推荐）

```js
const snap = await t.domSnapshot({ full: true })
// generic    "你好，PulseMind"    ← 标题
// paragraph  "你好呀"              ← 段落
// generic    "3字"                 ← 字数（可交叉校验）
```

### 2.2 校验

- 段落节点逐个列出，**读到的正文可直接与字数交叉验证**；
- 若页面停在 DLP 扫描（`iframeCount: 0` + `DLP 安全扫描中`）→ **正文不存在**，不是"读失败"，耐心等/报告用户（主文件 §0.5）。

## 三、写

### 3.1 定位器点击 + type（精确到字符）

```js
// ① 用定位器点中目标段落（★ 定位器在此类型可用）
await t.playwright(agent.playwright.getByText('你好呀'), 'click')
await t.waitForTimeout(300)
// ② 真实键入
await t.keyboard.type('要插入的内容')
await t.waitForTimeout(500)
// ③ 快照回读验证
const after = await t.domSnapshot({ full: true })
```

**实测（2026-09-27）**：`getByText('你好呀')` 点击 → `type('TEST')` → 快照可见写入 → **立即撤销恢复原样** ✅

### 3.2 安全纪律

- 这份文档也是**别人的工作文档**时：**写完立即回读 → 立即恢复**（撤销/删除测试内容）；
- 改动前后各做一次快照对比，**证据留存**（diff 即为写入证明）。

## 四、自检清单

**读之前**
- [ ] DLP 是否已完成（页面还在"扫描中"就**别动手**，先等/报告）

**写之前**
- [ ] 模式正确（按钮显示 `阅读` = 可编辑）
- [ ] 目标段落定位器已验证可命中（getByText 试一次）

**写之后**
- [ ] 快照回读对比（写入证据 + 无错位）
- [ ] 测试痕迹清理（恢复原值）

**收尾**
- [ ] 无需前缀/坐标处理（不要画蛇添足）

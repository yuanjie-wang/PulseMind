## 一、识别与前置

### 1.1 这是什么文档

| 特征 | 值 |
|---|---|
| 分享页 URL | `doc.cmbchina.com/f/v?id=<docId>&mode=edit` |
| 文档形态 | **多维表格**（网格化 + 字段/记录概念）|
| 内核 | WPS 系（跨域 iframe）|
| 单元格可访问名 | **坐标形式 `r1,f1`**（`r` = 行、`f` = 列）|
| 渲染 | canvas/画布型 —— DOM 里**没有**单元格文本，取数靠快照/剪贴板 |

**快速判定**：快照里单元格的可访问名形如 `r1,f1` → **本文档**（普通 Excel 是 `textbox "B3"`，Word 是文本段落节点）。

### 1.2 ★★ 前置：必须先进入编辑模式（血泪教训）

**点右上角「阅读」按钮 → 标签翻转为「编辑」→ 进入编辑模式后才能编辑。**

- 未进入编辑模式时：**所有写入操作都会失败**（键盘被吞、键入无反应）；
- 实测教训：曾把"写不进去"误判为"tippy 浮层不进快照无法验证"——**真正根因是模式没开**；
- 与主文件 §0.2 的模式语义一致（先看按钮标签再动手）。

## 二、读

### 2.1 快照 + 剪贴板（主力方案）

```js
// ① 快照拿结构（定位单元格的可访问名 r1,f1）
const snap = await t.domSnapshot({ full: true })
// ② 选中目标区域（坐标定位/点选）后：
await t.keyboard.press('Meta+c')          // ★ macOS 必须 Meta+c（Ctrl+c 静默失败，主文件 §0.6）
await t.waitForTimeout(300)
const text = await t.clipboard.read()     // TSV 形式
```

### 2.2 注意

- **读取依赖剪贴板** → 会**覆盖用户剪贴板**，操作完建议告知用户；
- 多维表格**暂无**类似 Excel `getRangeContents()` 的内部 API 读法（未验证，见 §五 待探清单）。

## 三、写

### 3.1 写入配方（坐标定位 + 真实键入 + 回读验证）

```js
// ① 确保已进入编辑模式（§1.2）★ 否则一切白费
// ② 定位到目标单元格（点击/键盘导航，ref 必须来自【当日快照】）
// ③ 真实键入（keyboard.type，不是 playwright fill）
await t.keyboard.type('内容')
await t.waitForTimeout(700)               // 内核异步渲染，给足时间
// ④ ★★ 必须回读验证 ★★
//    读法：⌘A → ⌘C → clipboard.read()（或快照交叉）
// ⑤ 出错 → ⌘Z 撤销 / 恢复原值
```

### 3.2 ⚠️ 验证的坑

**编辑层是 tippy 浮层 —— 不进 `domSnapshot`。**
→ **不能用快照"看到自己写的内容"来判断写入成功**；
→ 回读必须走**剪贴板**（或其它能反映真实值的通道）。

**实测数据点**：曾用此配方在 `r1,f1` 写入 `TEST123` 并成功回读 ✅

## 四、自检清单

**写之前**
- [ ] **编辑模式已开**（按钮显示 `阅读` = 可编辑）—— 最容易漏、代价最大
- [ ] 目标单元格坐标已确认（`r1,f1` 形式）
- [ ] 想好回读方案（剪贴板）

**写之后**
- [ ] **回读验证**（不是看快照！）
- [ ] 测试痕迹立即清理（恢复原值）

**收尾**
- [ ] 剪贴板被覆盖过 → 提醒用户
- [ ] 如误用裸接口（见 §五）→ 检查编辑器是否还能手动编辑
